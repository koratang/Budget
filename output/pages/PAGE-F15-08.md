## 2. 页面概述

### 2.1 一句话定位
跟踪年度重点工作的进度与状态，自动把延误、阻滞的工作拎出来。

### 2.2 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 统计正确 | 示例数据：15 项、已完成 2、平均进度 60%、需要关注 3（延误 2 · 阻滞 1）、进行中 10、分类覆盖 4 / 6 |
| 联动 | 改任一行后 KPI 与两分区立即刷新（AC-F15-07） |
| 校验 | 进度限制在 0–100（填 120 存为 100，FLOW-39） |

### 2.3 不做什么
- **不做**维度切换——页头无年度 / 月度控件。
- **不做**责任部门与财务影响字段——实现字段为时间、工作分类、工作目标、工作分解、预计完成时间、目前进度、工作状态。

## 3. 用户与场景

**场景 A**：陈思雨新增「Wayfair 美西新仓上线」，进度填 120，失焦后显示 100，年度重点工作变为 16 项，KPI 同步刷新。
**场景 B**：陈思雨把「仓储 WMS 二期」状态由「延误」改为「进行中」，该行从「需要关注工作」分区消失，需要关注变为 2 项。
**场景 C**：周明远查看，进度列为彩色进度条（按状态着色）+ 百分比，无编辑控件。

## 4. 信息架构

1. 页头（外壳，无维度切换）：标题 +「示例数据」、描述「年度重点项目立项 / 进度 / 责任部门 / 财务影响归因」
2. 口径说明卡
3. KPI 卡 ×4
4. 重点工作台账卡：标题 + 字段说明；「n 项」徽标 +「＋ 新增工作」；分区「年度重点工作」、分区「需要关注工作」（琥珀标题）；底部说明

## 5. 界面内容

### 5.1 KPI 卡

| 卡片 | 主值 | 脚注 |
| :--- | :--- | :--- |
| 年度重点工作 | 15 项 | 已完成 2 · 平均进度 60% |
| 需要关注工作 | 3 项（>0 琥珀，=0 绿） | 延误 2 · 阻滞 1 |
| 进行中工作 | 10 项 | 分类覆盖 4 / 6 |
| 分类覆盖 | 六个彩色分类标签：核算 2、资金 0、合规 4、降本增收 7、财务BP 0、信息化 2 | 已使用分类 4 / 6 项 |

### 5.2 台账表列（两分区同结构）

| 列 | 编辑者 | CEO |
| :--- | :--- | :--- |
| 时间 | 输入框「如 2026-04」 | 文本 |
| 工作分类 | 下拉：核算 / 资金 / 合规 / 降本增收 / 财务BP / 信息化 | 文本 |
| 工作目标、工作分解 | 输入框 | 换行文本 |
| 预计完成时间 | 输入框「如 2026-11」 | 文本 |
| 目前进度 | 数字框 0–100 + % | 进度条（进行中墨蓝 / 已完成绿 / 延误琥珀 / 阻滞红）+ 百分比 |
| 工作状态 | 下拉：进行中 / 已完成 / 延误 / 阻滞 | 文本 |
| 操作 | 「删除」→「确认删除」「取消」 | 不显示 |

年度重点工作按状态排序（进行中 → 已完成 → 延误 → 阻滞）；需要关注工作 = 状态为延误或阻滞的行（同一份台账派生，编辑任一分区等同编辑原行）。

## 6. 交互流程

```
新增 → push { 进度 0、状态 进行中 } → commit('keywork') → 提示需填写的 7 个字段
改格 → 进度 clamp 0–100 → commit('keywork') → KPI 与分区重算
删除 → 行内二次确认 → 提示「已删除第 n 行工作台账」
409 → 红色条「「重点工作」已被某某更新，请刷新后再改。…」+「刷新数据」
```

## 7. 状态与边界

| 状态 | 页面表现 |
| :--- | :--- |
| 分区无数据 | 年度：「该分区暂无工作记录」；关注：「暂无延误 / 阻滞工作」 |
| 进度非数字 | 存为 0 |
| 加载 / 错误 / 无权限 | 同外壳 |
