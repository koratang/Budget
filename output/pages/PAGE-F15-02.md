## 2. 页面概述

### 2.1 一句话定位
维护财务指标实际值，并按原工作台口径自动重算派生值、同比环比与勾稽。

### 2.2 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 口径一致 | 示例数据 F1 9,840、F2 3,092.6、F3 31.4、F4 553.9、F5 5.63、F4.9 = 七项费用率之和 25.8（FLOW-38） |
| 保存 | 改一格即自动保存到服务器，刷新后仍在（FLOW-37） |

### 2.3 不做什么
- **不做**目标值、权重的页内编辑——实现只开放「实际值」单元格；目标、权重通过 PAGE-F15-09 导入维护。
- **不做**达成率列——实现的明细表列为实际值 / 环比 / 同比 / 单位，达成率在业务指标页呈现（以实现为准，DESIGN-32 所列「目标、达成」列未在本页出现，见 §12）。

## 3. 用户与场景

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 财务BP 陈思雨（录入）、财务负责人 林晓（复核）、CEO 周明远（只读） |
| 频次 | 每月结账后 |

**场景 A**：陈思雨把「F1.1 Amazon」实际值改为 5,200，回车后页头出现「保存中…」，轻提示「F1.1 实际值 已更新，相关指标与建议已重新计算」；林晓刷新后看到 F1.1 = 5,200，F1 与勾稽同步更新。
**场景 B**：周明远打开本页，实际值列为纯文本，无输入框。

## 4. 信息架构

1. 页头（外壳）：标题 +「示例数据」、描述、年度 / 月度切换、期间
2. KPI 卡 ×7（F1–F7）
3. 财务指标体系明细：标题行（7 个一级 · 40 个二级）+ 层级筛选（全部 / 仅一级 / 仅二级）+ 搜索框；明细表
4. 财务视角关键提示（6 条）

## 5. 界面内容

### 5.1 KPI 卡
名称 + 编码、实际值（% / 天保留 1 位，其余整数）+ 单位、「环比 …」「同比 …」。有利变动红、不利绿（逆向指标反向判断）；无数据显示「—」。示例：F1 9,840 同比 +15.0%，F6 净资产收益率「—」。

### 5.2 明细表列

| 列 | 说明 |
| :--- | :--- |
| 层级 | 「一级」（墨蓝徽标，整行浅底加粗）/「二级」 |
| 编码 | F1、F1.1 … 等宽字体 |
| 指标名称 | 附徽标：逆向、派生（派生公式计算）、待填报、月度（月度维度）、手工填报（该月有手工覆盖） |
| 实际值 | 编辑者为右对齐输入框，占位「—」；CEO 为文本 |
| 环比 / 同比 | 百分比带正负号，涨红跌绿；无数据「—」 |
| 单位 | 人民币 / % / 天 |

筛选：一级按父子顺序展示子项；搜索匹配名称、编码、责任部门；无结果「没有匹配的指标，请调整筛选条件或搜索关键词。」

### 5.3 财务视角关键提示
毛利率缺口、期间费用率超标、存货周转天数超目标、净利润达成率、应收账期、经营净现金流达成率 6 条，图标 ✓ / ! / × 按偏差自动着色。

## 6. 交互流程

```
编辑者修改实际值 → change
  ├─ 引擎 editCell 校验失败 → 回填原值 + 轻提示错误原因
  └─ 成功 → 引擎重算 → commit('indicators')（500ms 合并）→ 页头「保存中…」→ API-F15-02
        ├─ 成功：revision+1，审计 bizfin.save
        └─ 409：页头下红色条「「财务与业务指标」已被某某更新，请刷新后再改。刷新会丢弃你刚才未保存的修改。」+「刷新数据」
月度维度下修改 = 写当月覆盖并反算年度累计，提示「…月度实际值已更新，年度累计值已同步反算，其余月份保持不变」
```

## 7. 状态与边界

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 加载 / 错误 / 无权限 | 同外壳 | 骨架；「业财分析数据加载失败」+「重试」；403 无权限 +「返回工作台」 |
| 保存失败（非冲突） | 网络等 | 红色条「「财务与业务指标」保存失败：…」 |
| 示例数据 | 五个部分中任一仍为示例数据 | 标题旁「示例数据」+ 说明条「尚有部分内容为原工具自带的示例数据…」 |

## 8. 页面流转
```
侧栏 → 财务指标（本页）；编辑结果被 PAGE-F15-01 / 04 / 05 读取
```
