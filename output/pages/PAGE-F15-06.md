## 2. 页面概述

### 2.1 一句话定位
登记影响经营的外部政策与事件，并写明对业务与财务的量化影响。

### 2.2 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 留痕 | 每次修改保存到服务器并写审计 `bizfin.save`（部分 policy） |
| 防误删 | 删除前必须二次确认 |

### 2.3 不做什么
- **不做**年度 / 月度维度切换——页头不显示维度控件（台账与期间无关）。
- **不做**等级、类别字段——实现字段为时间、业务板块、事件描述、事件影响（DESIGN-36 所列「类别、等级」以实现为准，见 §11）。

## 3. 用户与场景

**场景 A**：陈思雨点「＋ 新增事件」，台账末尾出现空行，提示「已新增事件行，请填写时间 / 业务板块 / 事件描述 / 事件影响」；填入「美国对进口浴室柜加征 10% 关税」，每格失焦即保存。
**场景 B**：陈思雨点该行「删除」，按钮原位变为「确认删除」「取消」；点「确认删除」后提示「已删除第 5 行政策事件」。
**场景 C**：周明远查看本页，无新增按钮，单元格为纯文本，无删除列。

## 4. 信息架构

1. 页头（外壳，无维度切换）：标题 +「示例数据」、描述「外部政策 → 业务指标 → 财务指标 的影响识别与影响量化」
2. 示例数据说明条
3. 台账卡：标题 + 说明；右侧条数徽标「n 条」+「＋ 新增事件」（仅编辑者）；台账表；底部说明

## 5. 界面内容

### 5.1 台账表列

| 列 | 编辑者 | CEO |
| :--- | :--- | :--- |
| 时间（128px） | 输入框，占位「如 2026-04-01」 | 文本 |
| 业务板块（140px） | 下拉：营销板块 / 产品板块 / 供应链板块 / 仓配履约板块 / 财务板块 / 综合；未选时首项空；历史值不在列表中时追加 | 文本 |
| 事件描述（36%） | 输入框，占位「政策 / 事件描述」 | 换行文本 |
| 事件影响 | 输入框，占位「对业务 / 财务的影响」 | 换行文本 |
| 操作 | 「删除」→「确认删除」「取消」 | 不显示 |

### 5.2 示例数据（4 条）
2026-01-02 供应链板块 美国 301 关税继续加征；2026-03-01 供应链板块 加州 65 号提案与甲醛限量收紧；2026-04-01 产品板块 STURDY 法案稳定性强制标准；2024-12-13 营销板块 欧盟 GPSR 强执法。

## 6. 交互流程

```
新增 → push 空行 → commit('policy') → 「保存中…」→ API-F15-02
改任一格（change）→ 写入引擎 → commit('policy')
删除 → 行内二次确认 →「确认删除」→ splice → commit('policy') → 轻提示「已删除第 n 行政策事件」
                     └「取消」→ 恢复「删除」
409 → 红色条「「政策环境事件」已被某某更新，请刷新后再改。刷新会丢弃你刚才未保存的修改。」+「刷新数据」
```

## 7. 状态与边界

| 状态 | 页面表现 |
| :--- | :--- |
| 空台账 | 「暂无政策事件记录」，编辑者追加「，点击右上角「＋ 新增事件」开始登记」 |
| 加载 / 错误 / 无权限 | 同外壳 |
| 保存失败 | 红色条「「政策环境事件」保存失败：…」 |
