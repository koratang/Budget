## 2. 页面概述

### 2.1 一句话定位

把驱动假设、预警规则、额度标准放在一处，按可信度和生效版本管理，经验可传承、每条可追溯。

### 2.2 存在理由

1. 预算经验散落在个人脑子里，人员变动即丢失（US-F12-01）。
2. 规则要标明可信度，避免把未经验证的经验当成定论（AC-F12-01）。
3. 首次部署即需要三条预警规则开始运转（AC-F12-03）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 状态清楚 | 每条规则都显示类型、生效版本（或无）、待审批版本（或无）、可信度 |
| 初始可用 | 首次部署后列表恰有 3 条预置预警规则，均为「未验证经验」、待审批（AC-F12-03） |

### 2.4 不做什么

- 不在列表上审批——审批在 PAGE-F07-02。
- 不删除规则——规则只出新版本（蓝图 §9）。

## 3. 用户与场景

**场景 A：首次部署后**：林晓打开规则库，看到 3 条「系统预置」预警规则，待审批 v1，可信度「未验证经验」→ 到待我审批中审批生效。

**场景 B：日常查看**：按类型标签切换，按可信度或「有待审批版本」筛选；看到「部门费用额度使用率超出时间进度 10 个百分点以上」生效 v1、待审批 v2（历史观察）。

**场景 C：新建规则**：陈思雨点「新建规则」进入 PAGE-F12-02 新建表单。

## 4. 信息架构

1. 类型标签：全部 / 驱动假设 / 预警规则 / 额度标准
2. 筛选：可信度（未验证经验 / 历史观察 / 已验证）、状态（有生效版本 / 有待审批版本）；「新建规则」
3. 可信度与审批说明一行
4. 规则列表 + 分页

## 5. 界面内容

| 列 | 内容 |
| :--- | :--- |
| 规则名称 | 链接到规则详情 |
| 类型 | 驱动假设 / 预警规则 / 额度标准 |
| 可信度 | 生效版本的可信度：未验证经验（预警色）/ 历史观察（中性）/ 已验证（有利色）；无生效版本显示「—」 |
| 生效版本 | 「生效 v1」或「无」 |
| 待审批版本 | 「待审批 v2（历史观察，待财务负责人审批）」或「—」 |
| 生效时间 | YYYY-MM-DD HH:mm |
| 最近提交人 | 姓名或「系统预置」 |
| 操作 | 查看 |

预置规则（AC-F12-03）：
1. 新渠道连续 2 个月收入达成率低于 70%
2. 部门费用额度使用率超出时间进度 10 个百分点以上
3. 品类毛利率比预算低 3 个百分点以上

原型另含额度标准「新渠道月收入放量上限（起始后第 1–12 个月逐月上限，人民币/店铺/月）」v1：数值由财务负责人填写，初始可信度「未验证经验」，经财务负责人与 CEO 审批后生效，供 PAGE-F04-02 判断新渠道超放量（AC-F13-02，design-derived DEC-F04-06）。

## 6. 交互流程

```
进入页面 → 默认全部类型
切换类型 / 可信度 / 状态 → 即时过滤
点规则名称或「查看」→ PAGE-F12-02 规则详情
点「新建规则」（仅财务BP、财务负责人可见）→ PAGE-F12-02 新建表单
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | 有规则 | 列表 |
| 筛选无结果 | 条件下无规则 | 「没有符合筛选条件的规则」 |
| 空 | 规则库为空（理论上首次部署即有 3 条预置） | 「规则库还没有规则」+「新建规则」 |
| 加载 | 请求中 | 骨架行 |
| 错误 | 请求失败 | 「数据加载失败」+ 重试 |
| 无权限 | 非财务BP / 财务负责人 / CEO | 无权限提示 |

## 8. 业务规则与校验

- 规则类型三选一；可信度三选一（AC-F12-01，表单校验见 PAGE-F12-02）。
- 新建保存后为待审批（AC-F12-01）；驱动假设、预警规则由财务负责人审批，额度标准再经 CEO（AC-F12-04）。
- CEO 看不到「新建规则」按钮。
