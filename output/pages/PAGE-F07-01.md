## 2. 页面概述

### 2.1 一句话定位

把轮到「我」审批的填报、目标调整和规则集中在一张列表里，点进去就能审。

### 2.2 存在理由

1. 三级审批（部门负责人 → 财务负责人 → CEO）要求每一级审批人都能找到待办（REQ-F07-01）。
2. 单位提交后须进入其部门负责人的待审核列表，并同时发钉钉工作通知（AC-F07-01）；没有列表，通知点进来也无处落地。
3. 目标调整（AC-F08-04）和规则（AC-F12-04）也走审批，统一入口避免审批人在多个页面找待办。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 到达正确 | 单位提交后，其部门负责人的待处理列表 100% 出现该单位（AC-F07-01） |
| 不越权 | 列表只出现当前环节审批人是「我」的事项；部门负责人看不到其他部门的事项 |
| 可追溯 | 已处理标签页能看到自己处理过的事项及结果（通过 / 退回及原因） |

### 2.4 不做什么

- 不在列表上直接通过或退回——审批前必须进入详情只读查看内容（REQ-F07-01、蓝图 §5「审批前弹窗确认」）。
- 不做「提交 CEO 审批」——该动作在 PAGE-F03-02 · 编制任务详情，并受 AC-F07-04 约束。
- 不做催办、转交、加签——Source IDs 未定义。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 部门负责人（15 个部门）、财务负责人林晓、CEO 周明远 |
| 使用时机 | 编制期（2026-12）集中审核；每季度目标调整；规则提交时 |
| 设备 | 办公电脑或钉钉内置浏览器 |

### 3.2 核心使用场景

**场景 A：部门负责人收到提交通知后审核**
- 时机：运营王浩提交「Amazon-US-01」填报（每个启用店铺一个单位，AC-F03-05）
- 动作：运营部负责人赵磊点钉钉通知 → 进入本页「待处理」→ 点「审批」进入详情

**场景 B：财务负责人处理目标调整和规则**
- 时机：2027-05-12，Q2 目标调整已有单位经部门负责人通过；陈思雨提交了两条规则
- 动作：按类型筛选「目标调整」或「规则审批」→ 逐条进入详情处理

**场景 C：回看已处理**
- 动作：切到「已处理」查看结果、退回原因

## 4. 信息架构

1. 标签页：待处理（数量）/ 已处理（数量）
2. 筛选：类型（全部 / 预算编制 / 目标调整 / 规则审批）
3. 说明行：新的待审批事项同时发送钉钉工作通知
4. 列表与分页（每页 50 条）

## 5. 界面内容

### 5.1 元素清单

| 列 | 内容 | 说明 |
| :--- | :--- | :--- |
| 类型 | 预算编制 / 目标调整 / 规则审批 | 中性徽章 |

| 提交人 | 填报人或规则提交人姓名 | — |
| 当前环节 / 结果 | 待处理：当前环节及前序结果（如「财务负责人审核（部门负责人赵磊已通过）」「财务负责人审批，之后需 CEO 审批」）；已处理：已通过 / 已退回 + 原因 | 已退回用不利色徽章 |

| 操作 | 待处理：「审批」；已处理：「查看」 | 跳 PAGE-F07-02 |

### 5.2 角色差异

| 角色 | 待处理中出现的事项 |
| :--- | :--- |
| 部门负责人 | 本部门填报单位提交的年度填报（运营由运营部负责人、物流比例由物流物控部负责人审核）；本部门单位的目标调整（第一级） |
| 财务负责人 | 财务BP 的填报；经部门负责人通过的目标调整（第二级）；驱动假设、预警规则、额度标准的第一级审批 |
| CEO | 财务负责人提交的全公司预算；目标调整整次终审（全部单位经财务负责人通过后，整次一条）；经财务负责人通过的额度标准类规则 |

## 6. 交互流程

### 6.1 页面加载

- 默认「待处理」标签、类型「全部」，按提交时间倒序。
- 服务端只返回当前环节审批人为当前用户的事项（NFR-003）。

### 6.2 核心流程

```
单位提交填报 / 目标调整 / 规则
    │
    ├─ 系统把事项放入当前环节审批人的待处理列表（AC-F07-01）
    └─ 同时向该审批人发送钉钉工作通知（仅含事项名称、对象、链接，不含金额 NFR-005）
            │
            ▼
审批人在本页点「审批」→ PAGE-F07-02 审批详情 → 通过 / 退回
            │
            ▼
事项移入「已处理」；若有下一级，进入下一级审批人的待处理
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | 有待处理事项 | 列表 + 数量 |
| 空 | 没有待处理事项 | 「当前没有待你审批的事项」+ 说明 + 「查看已处理」按钮 |
| 筛选无结果 | 当前类型下无事项 | 表格内提示「没有符合筛选条件的事项」 |
| 加载 | 请求中 | 灰色骨架行 |
| 错误 | 请求失败 | 「数据加载失败」+ 重试 |
| 无权限 | 非部门负责人 / 财务负责人 / CEO 直接访问 | 「你没有访问该页面的权限」+ 返回工作台；侧栏不显示该菜单（蓝图 §2） |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 同一单位被退回后重新提交 | 作为新的待处理事项出现；已处理中保留上一次退回记录 |
| 事项已被处理（多人同时打开） | 进入详情时显示「该审批事项已不存在或已被处理」（见 PAGE-F07-02） |

## 8. 业务规则与校验

- 审批顺序：部门负责人 → 财务负责人 → CEO（PRD §3.3.7；目标调整按 AC-F08-04：部门负责人、财务负责人逐单位审，CEO 整次终审；规则可退回且原因必填，AC-F12-07；规则按 AC-F12-04：驱动假设、预警规则由财务负责人审批，额度标准再经 CEO）。
- 本页只读，不产生数据修改。

            │
