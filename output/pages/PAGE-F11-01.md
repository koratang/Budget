## 2. 页面概述

### 2.1 一句话定位

偏差一超线就生成一条预警并钉钉提醒负责人；负责人在这里看清是哪条规则、哪个对象、超了多少，并写明处理说明。

### 2.2 存在理由

1. 偏差不用等月度会才发现（US-F11-01）。
2. 通知可能失败，系统内必须有可靠的记录与「通知失败」标识（AC-F11-05）。
3. 处理过程要留痕：谁、何时、怎么处理的（AC-F11-03）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 不重复 | 同一规则版本 × 对象 × 期间只有 1 条记录、只通知 1 次（AC-F11-02） |
| 可见失败 | 重试 3 次仍失败的通知 100% 标「通知失败」（AC-F11-05） |
| 不外发金额 | 钉钉通知内容 0 金额（NFR-005） |

### 2.4 不做什么

- 不在本页编辑规则——规则在 PAGE-F12-02。
- 不提供手动重发通知、删除预警、指派他人——Source IDs 未定义。
- 不在通知中放指标值或金额。

## 3. 用户与场景

**场景 A：收到预警后处理**：物流物控部何建国收到钉钉通知（规则名、对象「物流物控部」、期间 2027-04、链接）→ 打开预警中心 → 看到额度使用率超出时间进度 12.7 个百分点 →「标记已处理」并写「4 月集中支付全年海外仓年度服务费，属一次性预付，5–12 月不再发生该项支出」。

**场景 B：财务负责人巡检**：林晓看未处理 3 条、通知失败 1 条（TikTok Shop 新渠道连续 2 个月达成率低于 70%），打开详情看到发送与重试记录，线下告知负责人。

**场景 C：同一命中再次评估**：镜柜 2027-04 毛利率差在 BI 导入后生成（−3.5 个百分点），金蝶导入后重新评估更新为 −3.8 个百分点，记录变化中注明「未新增记录、未重复通知」。

## 4. 信息架构

1. 关键数：未处理、已处理、钉钉通知失败
2. 筛选：状态（默认未处理）、规则、通知状态；最近评估时间与触发导入
3. 预警列表 + 分页
4. 规则说明一行：只由生效版本生成、同一命中不重复、通知不含金额
5. 详情弹窗；标记已处理弹窗

## 5. 界面内容

### 5.1 列表

| 列 | 内容 |
| :--- | :--- |
| 规则（版本） | 规则名称 +（v1） |
| 对象 | 渠道 · 店铺 · 站点 / 部门 / 品类（全部平台渠道） |
| 期间 | YYYY-MM；连续月数规则写「2027-03 至 2027-04」 |
| 指标值 | 主值（如「+14.3 个百分点」「58.2%、64.1%」）+ 小字构成（如「使用率 47.6%，时间进度 33.3%」）；等宽右对齐 |
| 阈值 | 如「> 10 个百分点」「< 70%，连续 2 个月」「< −3 个百分点」 |
| 状态 | 未处理（预警色徽章）/ 已处理（中性徽章 + 处理人 · 时间）；已处理后指标值被更新时另显示「指标已更新」徽章与更新时间（DEC-F11-01） |
| 通知状态 | 已发送 / 重试中 / 通知失败（不利色徽章） |
| 操作 | 「详情」；未处理且当前用户是接收人时「标记已处理」 |

### 5.2 详情弹窗

- 规则与版本、对象、期间、指标值（含构成）、阈值、接收人、状态（已处理含处理人、时间、说明）
- 钉钉通知内容预览：「【预算预警】规则名（版本）/ 对象 / 期间 / 查看详情：预算管理平台 › 预警中心」——不含金额与指标值
- 发送记录：首次发送与每次重试的时间和结果
- 记录变化：生成时间与触发导入；再次命中时的指标值更新
- 「查看相关报表」按规则类型跳转

### 5.3 标记已处理弹窗

- 规则 · 对象 · 期间；「处理说明 *」；「取消」「确认已处理」

## 6. 交互流程

```
财务BP 确认一次金蝶或 BI 导入
   → 用全部生效预警规则重新评估受影响月份（AC-F11-01，只用生效版本 AC-F12-05）
   → 每个命中：
        ├─ 同一规则版本 × 对象 × 期间已有记录 → 更新指标值，不新增、不再通知（AC-F11-02）
        └─ 新命中 → 新建记录（规则名称与版本、对象、期间、指标值、阈值）
                    → 向接收角色发钉钉工作通知（AC-F11-04）
                        ├─ 成功 → 已发送
                        └─ 失败 → 每 5 分钟重试，最多 3 次 → 仍失败标「通知失败」（AC-F11-05）

接收人「标记已处理」
   ├─ 说明为空 → 「请填写处理说明」，不保存
   └─ 已填 → 状态改为已处理，记录处理人、时间、说明（AC-F11-03）
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | 有预警 | 关键数 + 列表 |
| 筛选无结果 | 条件下无记录 | 「没有符合筛选条件的预警」 |
| 空 | 从未产生预警 | 「目前没有预警」+ 说明 + 「查看预警规则」 |
| 加载 | 请求中 | 骨架行 |
| 错误 | 请求失败 | 「数据加载失败」+ 重试 |
| 无权限 | 无预警查看权限 | 无权限提示 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 规则出新版本后同对象同期间再次命中 | 规则版本不同，按新记录处理（AC-F11-02 以「同一规则版本」为界） |
| 已处理的记录再次命中被更新指标值 | 更新指标值，状态保持已处理，显示「指标已更新」，不重复通知（DEC-F11-01） |
| 非接收人 | 不显示「标记已处理」 |

## 8. 业务规则与校验

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 处理说明 | 确认已处理时 | 非空 | 「请填写处理说明」 |

- 接收角色：对象所属部门负责人、负责该渠道的运营、财务负责人；部门费用超额度时另加 CEO（AC-F11-04，具体按规则中配置的接收角色）。
- 钉钉通知只含规则名称、对象、期间和系统链接，不含金额（AC-F11-04、NFR-005）。
