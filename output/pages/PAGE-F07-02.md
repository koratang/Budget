## 2. 页面概述

### 2.1 一句话定位

审批人在一页里只读看清要批的内容和合计，然后通过或写明原因退回；CEO 通过即把全年预算锁成「年初原始目标」。

### 2.2 存在理由

1. 部门对自己的数负责，审批人要先看到内容再决定（US-F07-02）。
2. 退回必须有原因，否则填报人不知道改什么（AC-F07-02）。
3. CEO 拍板后目标不能被随意改动，是全年评估的基准（AC-F07-05）。
4. 目标调整和规则同样需要审批留痕（AC-F08-04、AC-F12-04、NFR-004）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 退回必有原因 | 未填原因的退回 100% 被阻止（AC-F07-02） |
| 锁定可靠 | CEO 通过后，任何角色对年初原始目标的直接修改 100% 被拒（AC-F07-05） |
| 只读 | 审批人在本页无法修改任何数值 |

### 2.4 不做什么

- 不在本页修改数值——审批人只读；需要修改时退回。
- 不做「提交 CEO 审批」与 CEO 退回后的单位退回——在 PAGE-F03-02 · 编制任务详情（AC-F07-04、AC-F07-06 后半段）。
- 不做加签、转交、撤回。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | 部门负责人（如运营部赵磊）、财务负责人林晓、CEO 周明远 |
| 频次 | 编制期集中；每季度调整；规则提交时 |

### 3.2 核心使用场景（四类单据）

**A. 单位填报审核（部门负责人）**：赵磊 2026-12-18 审核「2027 年度预算 · Amazon-US-01」（每个启用店铺一个单位，AC-F03-05），看店铺 × 站点 × 品类的全年销量、本币收入、人民币收入、毛利、毛利率及合计；通过或退回。

**B. 全公司预算审批（CEO）**：周明远 2026-12-28 审批「2027 年度全公司预算」，看全年收入、毛利、部门费用、净利润关键数，按季度与按渠道 / B端汇总；「通过并锁定」或退回财务负责人。

**C. 目标调整单位审核（部门负责人 → 财务负责人，逐个单位）**：林晓 2027-05-12 审核「2027 Q2 目标调整 · Amazon-US-01」，看调整原因与逐月「调整前 / 调整后 / 差额」，1–4 月已导入实际灰显不可调整。

**C2. 目标调整整次终审（CEO）**：全部 28 个调整单位经财务负责人通过后，周明远 2027-06-11 对「2027 Q2 目标调整」整次审批，看各调整单位的原因与全年人民币收入调整前 / 后 / 差额及合计；「整次通过」或整次退回财务负责人（AC-F08-04）。

**D. 规则审批（财务负责人；额度标准再经 CEO）**：林晓审批陈思雨提交的「部门差旅费人均月度额度 2,500 元（v1）」，看待审批版本内容、可信度、依据，与当前生效版本对照。

## 4. 信息架构

1. 头部卡片：类型徽章、状态徽章、提交人与时间、事项名称、只读提示、审批进度链（已完成 / 当前 / 待进行）
2. 内容区（按单据类型切换，见 5.2）
3. 底部操作栏（吸底）：本次通过后果的一句话说明 + 「退回」+「通过」（CEO 审批全公司预算时为「通过并锁定」）
4. 结果提示：处理后替换操作栏
5. 弹窗：退回（原因必填）、通过确认

## 6. 交互流程

### 6.1 页面加载

- 校验当前用户是该事项当前环节的审批人；否则显示无权限。
- 按单据类型加载只读内容与审批进度。

### 6.2 退回

```
点「退回」→ 弹窗
    │
    ├─ 原因为空点「确认退回」→ 字段标红，提示「请填写退回原因」，不退回（AC-F07-02）
    │
    └─ 原因已填 → 退回
         ├─ 单位填报：单位状态改为「已退回」、解除编辑锁定、填报页显示退回原因、钉钉通知填报人（AC-F07-03）
         ├─ 全公司预算（CEO）：编制任务退回财务负责人并显示原因；财务负责人在 PAGE-F03-02 把指定单位退回其填报人（AC-F07-06）
         ├─ 目标调整单位（部门负责人 / 财务负责人）：单位状态「已退回」，退回填报人并通知，填报人在填报页「调整模式」修改后重新提交（DEC-F07-01）
         ├─ 目标调整整次终审（CEO）：整次退回财务负责人并显示原因，财务负责人可把指定单位退回其填报人（DEC-F07-01）
         └─ 规则：版本状态「已退回」且不生效，向提交人显示退回原因，提交人可修改后重新提交（AC-F12-07）
```

### 6.3 通过

```
点「通过」→ 确认弹窗（说明后果）→ 确认
    ├─ 单位填报：单位状态「已通过」，计入编制任务进度
    ├─ 全公司预算（CEO「通过并锁定」）：保存为「年初原始目标」V1，此后任何角色不能直接修改其数值（AC-F07-05）
    ├─ 目标调整：单位经部门负责人、财务负责人逐个通过；全部单位通过后 CEO 整次通过，生成新的「调整后目标」版本，记录版本号、审批人、审批时间、调整原因，年初原始目标与此前版本不变（AC-F08-04）
    └─ 规则：驱动假设 / 预警规则 → 财务负责人通过即生成新版本并生效，原生效版本转历史；额度标准 → 财务负责人通过后转 CEO，CEO 通过后生效（AC-F12-04）
处理后：状态徽章更新，操作栏替换为结果说明，轻提示 3 秒
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 待审批 | 当前用户是当前环节审批人 | 内容 + 操作栏 |
| 已处理 | 刚完成通过 / 退回 | 状态徽章（已通过 / 已锁定为年初原始目标 / 已退回），结果说明，无操作栏 |
| 空 | 事项不存在或已被处理 | 「该审批事项已不存在或已被处理」+ 返回待我审批 |
| 加载 | 请求中 | 骨架行 |
| 错误 | 请求失败 | 「数据加载失败」+ 重试 |
| 无权限 | 非当前环节审批人 | 「你不是该事项当前环节的审批人，不能查看或处理」 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 退回原因只有空格 | 视为未填，按 AC-F07-02 阻止 |
| 重复点击确认 | 首次请求完成前确认按钮不可再次触发 |
| 锁定后有人尝试修改年初原始目标 | 任何入口均拒绝；变化只能通过季度目标调整产生新版本（AC-F07-05、PAGE-F08-01） |
