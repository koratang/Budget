## 2. 页面概述

### 2.1 一句话定位

管理一年里的所有预算版本：锁定的年初原始目标、每季度最多一次的调整后目标、每季度发布的滚动预测快照。

### 2.2 存在理由

1. 考核基准要稳定，原始目标永远保留（AC-F08-04）；同时目标要每季度贴近实际一次（US-F08-01）。
2. 管理层需要每季度更新的全年预期，并用不可修改的快照计算预测准确度（AC-F08-07）。
3. 第一季度刚开始时没有新信息，直接以原始目标发布快照，免去全员重填（AC-F08-09）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 频次约束 | 本季度已有 CEO 通过的调整时，发起入口 100% 被阻止（AC-F08-01） |
| 月份约束 | 已导入金蝶实际的月份在调整中 100% 不可修改（AC-F08-02） |
| 版本只增 | 任何操作都不改动既有版本数值 |

### 2.4 不做什么

- 不在本页审批调整——审批在 PAGE-F07-02。
- 不展示版本明细报表——版本对比在 PAGE-F08-02，偏差报表在 F10 各页。
- 不提供删除、重命名版本。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 主要角色 | 财务负责人林晓 |
| 填报人 | 运营王浩等，按季度提交调整 |
| 频次 | 每季度 1–2 次 |

### 3.2 核心使用场景

**场景 A：第一季度以原始目标发布快照（2027-01-08）**
- 前置：V1 已锁定；本季度尚无快照
- 动作：林晓点「以年初原始目标发布」→ 确认 → 生成「2027 Q1 滚动预测快照」，不需要填报人重新提交（AC-F08-09）

**场景 B：发起季度目标调整**
- 动作：林晓点「发起季度调整」→ 弹窗显示所属季度、可调整月份（尚未导入金蝶实际的月份）、开放单位（按 AC-F03-05 的全部填报单位，钉钉通知填报人）、审批顺序（每单位部门负责人 → 财务负责人逐个审，CEO 整次终审）→ 确认发起

**场景 C：填报人提交调整（2027-05-12，王浩）**
- 动作：在「我的目标调整」中看到 Amazon-US-01、Amazon-CA-01、Amazon-UK-01、Amazon-DE-01 四个单位的进度 → 点「继续调整」进入 PAGE-F04-02 调整模式 → 编辑 5–12 月（1–4 月锁定）、填写调整原因 → 提交 → 进入部门负责人审核

**场景 D：发起滚动更新并发布快照**
- 动作：发起 → 系统钉钉通知运营、B端业务、物流物控、财务BP，只开放本季度及以后月份（AC-F08-05）→ 填报人在各填报表格中更新 → 林晓点「发布快照」→ 生成不可修改快照（AC-F08-06、AC-F08-07）

**场景 E：本季度已调整过（2027-06-20）**
- 「发起季度调整」不可用，旁注「本季度已有一次经 CEO 审批通过的目标调整（V3，2027-06-12），2027-07-01 起可发起下季度调整」（AC-F08-01）

## 4. 信息架构

**财务负责人视角**
1. 工具行：预算年度选择；当前日期 · 所属季度 · 金蝶实际已导入至哪月；右侧操作按钮（发起季度调整 / 发起滚动更新 / 以年初原始目标发布〔仅第一季度且本季度未发布快照时〕）及不可用原因
2. 本季度进行中：目标调整卡片、滚动预测卡片
3. 版本列表：勾选两个版本 →「对比所选」

**填报人视角**
1. 我的目标调整：调整模式说明 + 本人负责单位（每个单位一行）的状态、提交时间、当前环节、进入填报页调整模式的入口
2. 本季度滚动预测更新提示与填报入口

## 5. 界面内容

### 5.1 元素清单

**版本列表列**

| 列 | 内容 |
| :--- | :--- |
| 选择 | 复选框，最多选 2 个 |
| 版本 | V1、V2、V3…（目标版本）；「Q1 快照」等（滚动预测快照） |
| 类型 | 年初原始目标 / 调整后目标 / 滚动预测快照 |
| 所属季度 | 年初原始目标为「—」 |
| 状态 | 已锁定（V1）/ 当前目标（最新调整后目标）/ 已被 Vn 替代 / 不可修改（快照） |
| 审批 / 发布 | 审批链或发布人 |
| 时间 | 审批通过或发布时间 |
| 调整原因 / 发布方式 | 调整原因原文；快照写「以年初原始目标发布」或「1–4 月实际 + 5–12 月最新提交驱动」 |

**本季度卡片**

| 卡片 | 字段 |
| :--- | :--- |
| 目标调整 | 状态（未发起 / 审批中 / 已生效 Vn）、发起人与日期、可调整月份、进度（如「28 个单位中已提交 24 个；部门负责人已通过 19 个；财务负责人已通过 12 个」）、下一步（「全部单位经财务负责人通过后，CEO 对整次调整一次性终审」）、去待我审批链接 |
| 滚动预测 | 状态（未发起 / 填报中 / 已发布快照）、发起人与日期、开放月份、提交进度、快照口径说明、「发布快照」按钮 |

**弹窗**

| 弹窗 | 内容 |
| :--- | :--- |
| 发起季度目标调整 | 所属季度、可调整月份、开放单位（全部填报单位，钉钉通知）、审批顺序（每单位部门负责人 → 财务负责人逐个审核；全部通过后 CEO 整次终审）；说明每季度最多一次、审批结束前不能再发起、填报人在各填报表格「调整模式」修改并填原因、通过后生成新版本且保留原始目标 |
| 发起滚动预测更新 | 所属季度、开放月份（本季度及以后）、通知对象（运营、B端业务、物流物控、财务BP，钉钉工作通知） |
| 以年初原始目标发布 | 说明直接用 V1 月度数据生成 Q1 快照，无需重新提交，发布后不可修改 |
| 发布快照 | 已导入实际月份用实际数、其余用最新提交驱动；列出尚未提交本季度更新的填报人；发布日期与所属季度 |

**填报人「我的目标调整」**

| 元素 | 内容 |
| :--- | :--- |
| 说明 | 「目标调整在各填报表格中以「调整模式」编辑：已导入金蝶实际的 1–4 月锁定，只能修改 5–12 月；提交时须填写调整原因。每个单位依次经部门负责人、财务负责人审核，全部通过后由 CEO 对整次调整一次性终审。」 |
| 单位列表 | 填报单位（每个启用店铺等，AC-F03-05）、状态、提交时间、当前环节、操作（开始调整 / 继续调整 / 查看 → 对应填报页调整模式） |

调整的编辑、已导入实际月份锁定（AC-F08-02）与调整原因必填（AC-F08-03）在填报页实现，见 PAGE-F04-02「调整模式」（DEC-F08-04）。

## 6. 交互流程

### 6.1 页面加载

- 财务负责人：按当前日期判断所属自然季度、本季度调整与滚动状态，决定按钮可用性。
- 填报人：只显示本人负责单位的调整。

### 6.2 核心流程

```
发起季度调整
  ├─ 本季度已有 CEO 通过的调整 → 按钮不可用，旁注原因（AC-F08-01）
  ├─ 本年度已有进行中的调整 → 按钮不可用，旁注「…正在审批中，审批结束前不能再发起」（DEC-F08-01）
  └─ 否 → 弹窗确认 → 按 AC-F03-05 开放全部填报单位的「尚未导入金蝶实际的月份」，钉钉通知填报人（DEC-F08-05）
         填报人在各填报表格「调整模式」编辑 → 提交（DEC-F08-04）
           ├─ 原因为空 → 「请填写调整原因」，不提交（AC-F08-03）
           └─ 提交 → 每单位：部门负责人 → 财务负责人（PAGE-F07-02）
                     全部单位通过 → CEO 整次终审（PAGE-F07-02）
                     CEO 通过 → 生成「调整后目标」Vn，列表新增一行，原版本保留（AC-F08-04）

发起滚动更新 → 钉钉通知四类填报人，只开放本季度及以后月份（AC-F08-05）；同一季度只发起一次（DEC-F08-02）
  → 发布快照：已导入实际月份取实际，其余取最新提交驱动计算值（AC-F08-06）；有未提交者时确认弹窗列出，按其最近一次提交计算（DEC-F08-03）
  → 生成不可修改快照，标注发布日期和所属季度（AC-F08-07）

第一季度：以年初原始目标发布 → 直接生成 Q1 快照（AC-F08-09）
```

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 正常 | 已有版本 | 卡片 + 版本列表 |
| 空 | 年度尚无版本（CEO 未审批全公司预算） | 「2027 年度还没有预算版本」+ 说明 + 「查看编制任务」 |
| 加载 | 请求中 | 骨架行 |
| 错误 | 请求失败 | 「数据加载失败」+ 重试 |
| 无权限 | 无预算查看权限的角色 | 无权限提示；非财务负责人不显示发起 / 发布按钮 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 选中超过 2 个版本 | 第三个勾选无效；「对比所选」仅在恰好 2 个时可用 |
| 调整进行中又点发起 | 不可用，旁注原因（DEC-F08-01） |
| 本季度已发起滚动更新 | 不再显示发起入口（DEC-F08-02） |
| 目标调整与滚动预测同时进行 | 两者是独立版本，互不覆盖（PRD §3.3.8） |

## 8. 业务规则与校验

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 季度调整次数 | 发起时 | 当前自然季度内已有 CEO 通过的调整则阻止 | 「本季度已有一次经 CEO 审批通过的目标调整（Vn，日期），下季度起可再发起」（AC-F08-01） |
| 可调整月份 | 编辑时 | 只允许修改尚未导入金蝶实际的月份 | 锁定月份不可编辑（AC-F08-02） |
| 调整原因 | 填报页调整模式提交时 | 非空 | 「请填写调整原因」（AC-F08-03，见 PAGE-F04-02） |
| 进行中调整 | 发起时 | 本年度无进行中的调整 | 按钮不可用 +「审批结束前不能再发起」（DEC-F08-01） |
| 以年初原始目标发布 | 显示条件 | 仅预算年度第一季度且本季度尚未发布快照 | 不显示按钮（AC-F08-09） |

- 审计：目标版本与目标调整的每次修改留痕 ≥ 3 年（NFR-004）。
