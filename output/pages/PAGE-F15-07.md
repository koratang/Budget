## 2. 页面概述

### 2.1 一句话定位
把指标偏差对应的改善动作与财务影响登记成台账，供经营会跟进。

### 2.2 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 留痕 | 修改即保存服务器，审计 `bizfin.save`（部分 advice） |
| 防误删 | 删除需行内二次确认 |

### 2.3 不做什么
- **不做**部门评分——实现只有建议台账（DESIGN-37 所写「部门评分」未实现，见 §11）。
- **不做**维度切换——页头无年度 / 月度控件。
- **不做**建议的自动生成——描述沿用原工具文案，内容由人工登记（示例数据 4 条）。

## 3. 用户与场景

**场景 A**：驾驶舱显示存货周转天数 77% 达成，林晓点「查看经营建议 →」，看到 2026-03 仓配履约板块的 ABC 分级补货建议与「周转天数降至目标，可释放占用现金」的影响评估。
**场景 B**：陈思雨新增一行建议，填写 5 个字段，每格失焦自动保存。
**场景 C**：周明远只看到文本台账，无新增与删除。

## 4. 信息架构

1. 页头（外壳，无维度切换）：标题 +「示例数据」、描述「基于指标偏差自动生成的改善动作与财务影响测算」
2. 示例数据说明条
3. 管理建议台账卡：标题 + 说明；「n 条」徽标 +「＋ 新增建议」（仅编辑者）；台账表；底部说明

## 5. 界面内容

### 5.1 台账表列

| 列 | 编辑者 | CEO |
| :--- | :--- | :--- |
| 时间（112px） | 输入框，占位「如 2026-04」 | 文本 |
| 业务板块（128px） | 下拉：营销 / 产品 / 供应链 / 仓配履约 / 财务板块、综合 | 文本 |
| 背景描述（27%） | 输入框，占位「背景 / 问题现状」 | 换行文本 |
| 管理建议（32%） | 输入框，占位「管理建议 / 改善动作」 | 换行文本 |
| 影响评估 | 输入框，占位「对业务 / 财务的影响评估」 | 换行文本 |
| 操作 | 「删除」→「确认删除」「取消」 | 不显示 |

### 5.2 示例数据（4 条）
2026-01 营销板块 渠道品效低于目标；2026-02 供应链板块 采购降本率低于目标；2026-03 仓配履约板块 存货周转天数超标；2026-04 产品板块 上架 SPU 数量低于目标。管理建议为 ①–④ 编号的改善动作。

## 6. 交互流程

```
「＋ 新增建议」→ 空行 + 提示「已新增建议行，请填写时间 / 业务板块 / 背景描述 / 管理建议 / 影响评估」→ commit('advice')
改任一格 → commit('advice')（500ms 合并）→「保存中…」→ API-F15-02
删除 →「确认删除」→ 提示「已删除第 n 行管理建议」；「取消」→ 恢复
409 → 红色条「「经营建议」已被某某更新，请刷新后再改。…」+「刷新数据」
```

## 7. 状态与边界

| 状态 | 页面表现 |
| :--- | :--- |
