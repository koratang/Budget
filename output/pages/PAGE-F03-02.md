## 2. 页面概述

### 2.1 一句话定位

让财务负责人随时看清谁交了、谁逾期、谁被退回，并在全部通过后提交 CEO 审批。

### 2.2 存在理由

1. 28 个填报单位分散在 15 个部门，靠人工催收容易漏（US-F03-01）。
2. 未全部通过部门审核就提交 CEO，会把未确认的数送上审批（AC-F07-04）。
3. CEO 退回后需要把意见落到具体单位（AC-F07-06）。

### 2.3 页面目标

| 目标维度 | 具体指标 |
| :--- | :--- |
| 进度可见 | 五种状态与提交率实时可见（AC-F03-03） |
| 逾期提醒 | 截止次日 09:00 自动提醒未提交单位（AC-F03-04） |

### 2.4 不做什么

- 不在本页审核单位填报——在 PAGE-F07-02 审批详情中通过或退回。
- 不手动发送催办——提醒由系统按 AC-F03-04 自动发送。
- 不展示预算金额汇总——本页只管进度。

## 6. 交互流程

```
提交 CEO 审批
  ├─ 存在未「已通过」单位 → 弹窗「还不能提交 CEO 审批」，列出全部未通过单位名称及状态（AC-F07-04）
  └─ 全部已通过 → 确认「审批通过即锁定为「年初原始目标」」→ 任务状态「待 CEO 审批」，按钮变为「已提交 CEO 审批」禁用

CEO 退回后（任务状态「CEO 已退回」，AC-F07-06）
  → 对指定单位「退回给填报人」→ 原因为空提示「请填写退回原因」（AC-F07-02）
  → 确认 → 单位状态「已退回」，退回原因显示「林晓：…」，解锁并通知填报人（AC-F07-03）
  → 该单位重新提交并通过后，才能再次提交 CEO 审批

筛选：状态 / 类型 / 只看逾期，即时过滤；无结果显示「没有符合条件的填报单位」
```

| CEO 已退回 | AC-F07-06 | 显示 CEO 原因；已通过单位可被退回给填报人 |

## 8. 业务规则与校验

- 提交率 = （已提交 + 已通过）÷ 全部参与单位，已退回不计入，保留 1 位小数（AC-F03-03、DEC-F03-03）。
- 参与单位按 AC-F03-05 划分（28 个：9 个店铺、2 个 B 端部门、成本比例 1、物流比例 1、15 个部门），每个单位独立提交、审核、退回。
- 逾期：截止日期次日 09:00 起，状态不是已提交或已通过的单位为逾期；系统在该时点向填报人及其部门负责人发送钉钉逾期提醒（AC-F03-04）。
- 退回给填报人：原因必填（DEC-F03-02，沿用 AC-F07-02 的审核退回规则）。
