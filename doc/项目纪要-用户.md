## 决策记录
- 产品流程｜背景：用户要求安装五大 Master 后做预算平台｜结论：从解题大师从头梳理｜来源：用户

- 第一刀决策｜背景：预算要服务定目标/盯偏差/评结果｜结论：先改进「定目标」，现实痛点是4个月销售预测偏乐观→采购过量→库存积压｜来源：用户
- 范围调整｜背景：用户澄清预测准确率与库存健康度已有专项项目｜结论：本题是年度全面财务预算，专项项目的销售预测作为预算输入｜来源：用户
- 主结果指标｜结论：净利润达成率｜来源：用户
- 控制回路｜结论：部门费用视为基本固定成本，列示不作杠杆；题型=分配+偏差预警+归因｜来源：用户
- 前身经验｜结论：品类预算缺失、新渠道过乐观、固定费用增长快是上次的坑，本次需针对性设计｜来源：用户
- 解法路线｜结论：路线二 轻量预算平台（驱动因子模型、目标版/预测版分离、月度金蝶实际对比归因）｜来源：用户
- 输出形态｜结论：偏差报告+预警规则，不自动执行｜来源：用户
- 成功标准｜结论：2027年1-6月试运行；月度净利预测±1.5个点；固定费用增速≤收入增速；上半年净利达成率90%-110%｜来源：用户
- 规则库与最小切口｜结论：建预算规则库（财务负责人审批，目标/额度由CEO审批）；数据小试→Amazon美国站回测→全渠道；金蝶、BI、SKU对照表均由财务BP导出｜来源：用户
- PRD 范围与规则｜结论：完整闭环；现金流后置；专项预留额度；钉钉登录；Excel 导入；不接大模型；公共费用不分摊；目标可季度调整、评估按原始目标；物流费按收入比例；新品=上架未满12个月；品类收入=SPU数×品效｜来源：用户（state.json）
- 毛利口径与排期｜结论：毛利率=(收入−退款−采购−佣金−推广−头程−尾程−关税−仓储+库存索赔−其他运营费用)÷收入，B端同口径；库存索赔/其他运营费用由财务BP按渠道×站点填；钉钉应用11-30前就绪，12-01发布编制、12-31前CEO审批｜来源：用户
- 登录页扫码方式｜背景：视觉评审 DESIGN-01 要求页面直接显示钉钉二维码｜结论：按钉钉「扫码登录第三方网站」内嵌方式用 iframe 嵌钉钉登录页、postMessage 收临时登录码后带 loginTmpCode 完成授权，不加载 CDN 脚本；替身用 segno 本地生成二维码；内嵌参数与消息格式待真实凭据就绪后按官方文档核对（见 app/backend/README.md）｜来源：用户
- 审计时间口径｜背景：多处页面时间取审计表数据库 now()，与注入时钟不一致｜结论：write_audit 的 occurred_at 改取 clock.now()（生产等同当前时间）｜来源：AI

- 真实环境验收暂缓｜背景：10 行验收依赖真实钉钉、Windows、公司服务器、Edge/钉钉浏览器｜结论：本轮跳过，台账保持 pending 不计 pass，环境就绪后复验｜来源：用户

- Windows 试用包｜背景：用户要可试用版本｜结论：deploy/windows/build-trial.sh 生成免安装包（嵌入式 Python + 便携 PostgreSQL + VC++ 运行库 + 开发身份 + 演示数据），已在 wine 中验证应用链路；PostgreSQL 便携版因 wine 限制未在模拟环境运行，需真 Windows 确认｜来源：用户/AI

- 2026 经营数据接入｜背景：用户 10-28 上传 2026 年经营分析表（各渠道店铺毛利 + 管理费用），要求作 2027 编制参考与同比｜结论：新增「经营历史表」导入（缺主数据一键补建）、填报表格上年同月参考行、渠道×站点与部门费用报告同比；requirements r5（REQ-F09-03、REQ-F04-06、REQ-F10-07）｜来源：用户
