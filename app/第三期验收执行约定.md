# 第三期验收执行约定

目标：按 `output/tests/TDD验收契约.md` 逐行真实执行验收，发现产品缺陷就修产品，记录证据。证据规则以已安装 tdd-master 的 `references/TDD验收契约规范.md` §7 为准（不抄副本）。

## 分工与隔离

| 执行者 | 负责验收行 | 应用库 | 测试库 | 后端端口 | 钉钉替身端口 | 证据文件 |
|---|---|---|---|---|---|---|
| E1 | SMOKE-03、FLOW-01~10 | budget_acc1 | budget_test_acc1 | 8011 | 8021 | output/tests/evidence/E1.md |
| E2 | FLOW-11~20 | budget_acc2 | budget_test_acc2 | 8012 | 8022 | output/tests/evidence/E2.md |
| E3 | FLOW-21~32 | budget_acc3 | budget_test_acc3 | 8013 | 8023 | output/tests/evidence/E3.md |
| E4 | RULE-01~09 | budget_acc4 | budget_test_acc4 | 8014 | 8024 | output/tests/evidence/E4.md |

SMOKE-01/02、RULE-10、DESIGN-* 由主控执行。不要编辑 `output/tests/TDD验收结果.md`（主控合并），不要改契约与上游文档。

## 执行方法

1. 每一行都在**集成后的完整系统**上从契约写明的初始状态执行到终点（不是只跑单组服务测试）：后端接口用真实 HTTP（httpx/TestClient 均可，但必须经过真实路由、权限与数据库），行中写明「浏览器 E2E」的步骤用 Playwright 驱动真实运行页面（`npm run build:dev` 产物由后端托管，用 `/api/dev/login-as` 切换身份）。
2. 把每行的场景写成可重复运行的验收测试：`app/backend/tests/acceptance/test_<id 小写>.py`（API 层）和/或 `app/frontend/e2e/<id 小写>.spec.mjs`（浏览器层，用 node + playwright 直接运行）。期望值逐字取自契约，不由实现生成。已有的组内测试可复用其中正确部分。
3. 钉钉：用本地替身（DINGTALK_BASE_URL 指向你的替身端口）执行同一断言；契约规定标注「钉钉」的行须在真实钉钉复验后才可记 pass，所以这些行即使替身通过也记 `pending`，在证据中写清「本地替身已通过：…；待真实钉钉复验（凭据 2026-11-30 前就绪）」。
4. 发现失败先判断：产品缺陷→修产品代码（最小改动，只改与该缺陷相关的文件，改后跑 `pytest -q`（用你的测试库）与 `npm run build` 确认无回归）；测试错误→修测试。不要为了通过而改断言或降低标准。修复涉及别人负责的行时，在汇报中说明。
5. 证据文件格式（只写你负责的行，每行一条，表头固定）：

```
| TDD ID | 状态 | 实际验证动作 | 证据 |
| :--- | :--- | :--- | :--- |
| `FLOW-11` | pass | 运行 pytest tests/acceptance/test_flow_11.py（真实路由 + 数据库）并以 Playwright 在 PAGE-F04-02 填写同一单元 | command=…; exit_code=0; passed=3; failed=0; 关键观测值：收入 USD 8,640.00 … |
```

状态只用 pass / pending / fail。无法在本环境执行的写 pending 并说明原因。
