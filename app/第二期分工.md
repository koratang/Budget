## 跨组接口（固定签名，按此实现或调用）

审批由 G2 的 `api/approvals.py` 统一对外（类型：`unit` / `task` / `adjustment-unit` / `adjustment` / `rule-version`），按类型分发到服务模块。每个服务模块提供：

```python
def pending_items(db, user) -> list[dict]      # 待当前用户审批的事项：{type, id, title, kind_label, prev_step, submitted_at, link}
def detail(db, user, obj_id) -> dict           # 审批详情只读数据
def approve(db, user, obj_id) -> dict
def reject(db, user, obj_id, reason: str) -> dict   # reason 为空抛 422「请填写退回原因」
```

- `services/approval_units.py`（G2）：unit、task。
- `services/adjustments.py`（G3）：adjustment-unit、adjustment（CEO 整次终审）。
- `services/rules.py`（G3）：rule-version（额度标准类需 CEO 二级审批）。
- G2 在 G3 模块尚未提供时用 `importlib` 安全导入，缺失则该类型返回空列表；G3 完成后无需 G2 改动即可生效。

其他跨组读取：直接查询模型表，或调用 `app/calc/` 纯函数；不得修改别组的服务模块。G4 的报表读取 G2 写入的预算表与 G3 写入的实际数表；测试时在自己的测试里直接构造数据。

- `scripts/seed.py`：不改；需要额外样例数据写 `scripts/seed_g1.py` 等（只写主数据或前置条件，不预先完成待验收动作）。

## 每组完成标准

1. 后端接口实现技术方案 §4.9 中本组 API 与 requirements 中本组全部 AC；服务端范围过滤与审计。
2. 前端页面照 `output/pages/PAGE-*.html` 原型与 `PAGE-*.md` 页面说明实现（区域顺序、组件、文案、四态、交互），只用 tokens/app.css 与 Element Plus。
3. `pytest tests/<组>` 全部通过；负责的每个验收行有对应的场景测试且通过；`npm run build` 通过。
4. 用开发身份在真实运行的前后端里把本组页面点一遍（Playwright），确认无脚本错误。截图不用存档（视觉验收第三期统一做）。
5. 不 commit / push（主控统一提交）。汇报 ≤ 250 字：完成的接口与页面、测试结果最后一行、未完成或偏离项。
